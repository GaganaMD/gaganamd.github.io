# _build: source of the site's HTML pages

This folder is the source of truth for the generated pages of gaganamd.github.io.
GitHub Pages builds this repository with Jekyll, and Jekyll never publishes folders whose
names start with `_`, so `_build/` is version-controlled here but not served on the site.

## What is generated and what is not

| Generated by `build.py` (do not edit by hand) | Maintained by hand in the repo root |
|---|---|
| `index.html`, `research.html`, `detection-is-not-containment.html`, `writing.html`, `about.html`, `speaking.html`, `consulting.html`, `projects.html` (redirect), `404.html` | `styles.css`, `script.js`, `speaking.js`, `assets/`, `sitemap.xml`, `robots.txt`, `cv/`, `cv.pdf` (built by the CV GitHub Action) |

## Files

- `build.py`: the shared page shell (head and meta tags, navigation, footer, contact block) and the writer.
- `content.py`: the list of pages with their titles, descriptions and structured data; it reads each page body from `pages/`.
- `pages/*.html`: the main content of each page. **Edit these to change page text.**
  `projects.html` (a redirect to the research page) and `404.html` have no file here; their short bodies are written inline in `content.py`.
- `requirements.txt`: PyYAML and Markdown, pinned. Install once with `py -m pip install -r _build\requirements.txt` (Python 3.9+).
- `render.py`: reads `_content/` (YAML and Markdown) and renders it as HTML fragments.

## Rebuild

```bash
cd path/to/pp
python _build/build.py        # or python3 on macOS/Linux
git diff --stat               # only the pages whose source you changed should differ
```

The script overwrites the nine generated HTML files in the repository root and nothing else.
Rebuilding without edits reproduces the committed pages byte for byte; if `git diff` shows
changes you did not make, stop and check before committing.

## Updating News on the homepage

Edit `_content/news.yml` (the `_content/` folder is never published). Each item:

```yaml
- date: "2026-11-10"
  text: >-
    Our paper *Title* is [on arXiv](https://arxiv.org/abs/...).
```

`date` is `"YYYY-MM"` or `"YYYY-MM-DD"` (keep the quotes); `text` is one line of Markdown. Items are
sorted newest first automatically; the newest five are shown and the rest go under "Older news"
(change `NEWS_VISIBLE` in `content.py`). Then rebuild.

## Updating publications

Edit `_content/publications.yml`: one entry per paper or report. The file's header lists every field.
Order in the file is the order on the Research page (grouped under Peer-reviewed / Reports /
Manuscripts); entries with a `home:` block also appear in the homepage "Research papers" list,
sorted by `home.order`. Keep `authors` in the officially published order and set `me` to the exact
form of your name used there. Then rebuild.

## Light and dark themes

Light is the default. The header button switches to dark and the choice is remembered in the
visitor's browser. Dark mode only changes the colour variables at the top of `styles.css`
(`:root[data-theme="dark"]`); layout and type are shared.

## Before every commit and push

```bash
python _build/build.py
python _build/check.py   # must print OK
```

`check.py` fails if any page links a stylesheet or script whose `?v=` fingerprint doesn't match the
file on disk, or if a generated page is out of date. This is what keeps new HTML and the stylesheet
in step, so a returning visitor can never get the new page with an old stylesheet.

## Changing navigation, footer or meta tags

Edit `NAV`, `FOOTER`, `contact()` or `page()` in `build.py`. These affect every page.

## Previewing locally

```bash
python -m http.server 8000    # from the repo root, then open http://localhost:8000
```
